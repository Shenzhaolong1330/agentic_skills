# Jev 与 Astra 原子技能编排

本 skill 位于 `/home/deepcybo/agentic_skills/jev_skill`。这里的 Astra 指承担规划的模型，不是同名的 MatrixOrigin 运行框架。本 skill 定义协作协议，复用现有执行器；不包含模型权重，也不自动安装、配置或启动模型服务。

## 职责与入口

- **Astra**：解释用户目标与授权范围、选择机械臂和坐标系、生成步骤与候选动作、处理新情况和重新规划。在环境确实提供 Astra 时使用它；不可用时如实说明实际规划模型，不冒称 Astra，也不为模拟两种职责而自行启动子代理。
- **Jev**：接收结构化状态，在 Astra 提供的有限候选中作语义判断，例如选目标、选技能、重新观察或交回规划。只接受实际服务返回的选择，不能用自身猜测冒充 Jev 调用。
- **执行器**：计算数值、检查参数和前置条件，调用现有原子 skill，读取真实反馈。模型选择不替代工作空间、碰撞、故障、单位与数值阈值检查。

首次需要 Jev 时读 [Jev 接入与决策协议](references/jev-protocol.md)。选择本地能力时读 [原子 skill 调用指南](references/atomic-skills.md)，再读取选中原子 skill 自身的 `SKILL.md`。不要为简单拍照或已确定的下一步重复询问模型。

## 原子 skill 调用范围

**允许调用 `/home/deepcybo/agentic_skills/atomic_skills` 下的原子 skill**，包括现有和以后新增的能力。使用时发现实际入口：

```bash
rg --files /home/deepcybo/agentic_skills/atomic_skills -g SKILL.md
```

把需要的 skill 路径和现有脚本映射成动作白名单。Jev 只能返回候选 ID；不能直接执行它生成的命令、路径或任意代码。新增候选应先由 Astra 核对对应 skill 的真实接口。

调用许可用于完成用户当前任务，不自动授权回零、释放物体、初始化夹爪或其他额外动作。沿用会话中已有授权和现场确认；没有实质新问题时直接完成任务，不重复请求同一确认。仅当必要信息确实缺失或目标超出已有授权范围时，先完成可独立完成的准备，再说明具体缺口。

## 执行流程

1. **形成任务约定。** 从最新指令和上下文确定目标、左右臂、参考坐标系、米/弧度单位、速度、动作顺序、完成条件及步骤依赖。仅规划请求使用 dry-run；明确运动请求在条件满足时使用对应 skill 的真实执行参数。不要把过去示例中的机械臂、位姿或现场确认当成新任务的事实。
2. **观察与计算。** 获取本次新鲜反馈；相对位移从当前实测位姿计算一次并固定绝对目标，记录时间、frame 和起点。只平移时保持目标姿态。若观测标注 `torso` 而接口文档称 base，核对实际接口及坐标变换，不能重命名 frame 或直接混用。相机坐标先按所选相机标定转换。
3. **构造可执行候选。** 按授权、前置条件、参数边界和预算过滤候选，再让 Jev 判断。给每个候选绑定不可变参数和状态版本；新观察或计划变更后丢弃旧选择。已明确的动作顺序和可计算的比较由程序直接处理。
4. **执行一个步骤并核验。** 同一机械臂的动作按序执行，避免其他控制器同时写入目标；同一相机串号只允许一个采集者。使用原子执行器完成平滑轨迹，Jev 不参与伺服控制。保留命令回复，等待本步骤完成或明确结束后读取反馈。
5. **决定后续步骤。** 用下面的结果规则先排除硬故障，再检查依赖；只在存在语义选择时调用 Jev。目标不明、重复无进展或候选不足时交回 Astra。Jev 不可用时记录降级并由规划者在同样约束下继续；用户要求必须使用 Jev 时暂停依赖该判断的动作并说明缺失配置。
6. **如实汇报。** 分别报告命令是否发送、实测结果、容差是否满足、后续动作是否执行及是否有到位证据。涉及照片时返回本次生成的文件，不以历史图片代替。

## 结果与步骤依赖

不要用一个 `ok` 同时表示“已发指令”“物理到位”和“可以继续”。每步至少记录：

| 字段 | 含义 |
|---|---|
| `command_status` | `not_sent`、`acknowledged`、`rejected` 或 `unconfirmed` |
| `execution_status` | `not_started`、`in_progress`、`finished` 或 `unknown`；进程退出不自动证明远端运动结束 |
| `goal_status` | `met`、`not_met` 或 `unknown`，由实测反馈决定 |
| `fault_status` | `clear`、`active` 或 `unknown`；空错误字典不自动等于完整健康诊断 |
| `continuation_policy` | 下一步要求 `requires_goal`，或允许 `after_attempt` |
| `evidence` | 起点、目标、末位姿、误差、相机文件、夹爪反馈及时间戳 |

- `requires_goal`：下一步物理上依赖上一目标，例如夹稳后抬升、对孔后插入；未达到前置条件就不能继续该步骤。
- `after_attempt`：用户明确允许上一动作未到位也继续，且下一步不依赖它到位。运动已结束、反馈可用、无活动故障且下一步自身条件满足时，即使 `goal_status=not_met` 也继续。无需再问用户是否坚持原指令。
- 不能把 `after_attempt` 理解为忽略急停、障碍、通信不确定性或硬件故障。通信中断时标记 `unconfirmed`，停止新的物理动作并做只读诊断；不要自动重发相对运动，也不要声称机器人已停止。
- 进程退出码为 0 仍须检查返回 JSON。P2P 的 `result.ok=false` 可能只表示超出容差，须结合 `final_error`、遥测和故障证据判断。
- 夹爪“开合一次”通常是打开一次再关闭一次，明确侧别；依次验证两次动作。检查反馈的新鲜度及请求目标与本次命令是否对应，不能拿上一次 `requested_position_reached=true` 当作本次成功。空夹爪开合无需虚构夹持物体；抓取任务还需夹持证据。

## 重试与恢复

优先使用原子 skill 内置的有限修正，不在外层重新执行完整相对位移。若仍未到位，记录原目标和剩余误差，按依赖决定继续或交回 Astra。

每个计划记录有限步骤和重试预算；缺省对同一子目标最多允许一次有新证据、实质改变方案的外层重试，并保持原绝对目标。累计位移和补偿不能超过已验证边界。无新进展时停止重复尝试；用户允许后续独立动作时执行它们。重试预算不授权重放结果不明的运动。

恢复不能偷换成回零。本地 reset skill 可能使双臂回 home 并打开夹爪；只有其检查和任务授权都覆盖这些副作用时才执行。正常状态读取不得触发 reset。

## 应用示例

- “右臂 -X 20 cm，无论到位与否都开合一次”：固定目标为本次右臂 X 减 0.20 m；后续开合采用 `after_attempt`。仅容差失败时执行开合，并分别报告实际位移和开合结果。
- “抓起试管并插入孔”：感知、抓取、抬升、插入按实际依赖设置 `requires_goal`；Jev 可在重拍或重新规划之间选择，不能凭概率宣告抓稳。
- “用 object_locator 拍右手照片”：调用该原子 skill 的采图入口，返回新照片；已有确定流程时记录 `decision_source=deterministic`，不浪费一次 Jev 或 Astra 请求。
